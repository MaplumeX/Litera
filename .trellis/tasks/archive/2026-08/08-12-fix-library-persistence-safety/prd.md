# 修复书库持久化与文件安全

## Goal

保证书库元数据、EPUB、封面和阅读状态在并发调用、进程中断、重复导入和删除过程中始终一致，并阻止任何书库目录之外的文件操作。

## Requirements

- **LIB-1**：所有 `library.json` 读改写共享同一串行化边界；读取、解析和写入错误必须向调用方传播，不能回退为空书库。
- **LIB-2**：书库写入使用同目录原子替换；中断或写入失败后保留最后一个完整版本。
- **LIB-3**：所有 `bookId` 在文件操作前验证；删除目标从受信任的应用数据根派生，并校验目标仍位于 `books/` 下；不存在的书返回明确错误。
- **LIB-4**：`save_book_metadata` 必须先确认书籍记录存在再写封面；删除书籍时元数据和文件操作具有可恢复顺序。
- **LIB-5**：重复导入同一路径时，保存的 EPUB、返回给前端的字节、元数据和封面来自同一份内容，不保留旧文件配新元数据。
- **LIB-6**：同步文件 I/O 不在 Tauri 主线程或异步 runtime 核心线程直接执行。
- **LIB-7**：阅读位置和设置的防抖更新支持 cancel/flush；返回书库和关闭应用前提交最后状态；迟到更新不得复活已删除记录。
- **LIB-8**：对 fraction、字体设置和路径/ID 输入进行边界验证并返回结构清晰的错误。

## Acceptance Criteria

- [ ] 并发更新 fraction 与 settings 最终同时保留，两项都不会被旧快照覆盖。
- [ ] 更新与删除并发时，最终结果只能是完整存在或完整删除，不能出现指向缺失文件的复活记录。
- [ ] 无效 JSON、无权限读取和写入失败都会保留原文件并向前端报告错误。
- [ ] 绝对路径、`..`、路径分隔符、空 ID 和未知 ID 均不能造成 `books/` 之外的写入或删除。
- [ ] 重复导入修改后的同路径 EPUB 后，打开内容、标题、作者和封面对应同一版本。
- [ ] 返回书库或正常关闭后重新启动，最后一次阅读位置和设置仍然存在。
- [ ] Rust 自动化测试覆盖原子写、并发读改写、损坏 JSON、路径穿越、重复导入和删除回滚；相关前端测试覆盖 debounce flush/cancel。

## Constraints

- 新版本继续使用应用数据目录中的 `library.json` 与 `books/<bookId>/` 布局，但允许增加存储版本并重置旧数据。
- 文件选择取消保持非错误 UX。
- 现有 CSP 和 asset protocol 范围不能扩大到书库目录之外。
- 旧数据先移动到带时间戳的备份目录；备份失败时不得继续重置。

## Out of Scope

- 改用外部数据库或云同步。
- 书库 UI 重设计。
