# 修复用户消息编辑与消息操作按钮占位

## Goal

用户能在气泡里改自己的提问；保存后当前视图从该条截断，并用新文本重新生成。编辑/复制按钮有独立占位，不再压在正文上。

## Background

当前「编辑」只是把原文填回底部输入框再追加一条。父任务要求的是编辑态。按钮用 `absolute` 叠在文字右上角，短消息和助手首行会被挡住。

用户已确认：ChatGPT 式截断重发；旧分支不在 UI 里切换。

## Requirements

### R1 气泡内联编辑

- 每条用户消息可进入编辑态：气泡变成可改文本，带保存 / 取消。
- 取消：退出编辑态，原文与历史不变。
- 保存：空文本不可提交；用新文本从该条截断后重发。
- 流式生成中不可进入编辑。
- 原消息带选段引用时，重发保留该 `selection` / `chapterIndex`（只读展示引用卡片）。会话重载后本来就没有选段字段，则不伪造。

### R2 截断后重发

- 可编辑当前会话里任意一条可见的用户消息，不限最后一条。
- 保存后，该条及其后的消息从当前视图消失，新提问出现在截断点，并生成新回复。
- 同一会话文件内用 pi 树分支实现；旧路径留在 JSONL，本轮不暴露切换器。
- 走新协议命令（见 design），不把截断塞进现有 `prompt` 的可选字段以免误伤普通发送。

### R3 操作按钮占位

- 用户消息：气泡下方固定操作行，放编辑按钮。
- 助手消息（有正文时）：内容下方固定操作行，放复制按钮。
- 图标可 hover 才加深，但行高始终占位，不得 `absolute` 叠在正文上。
- 编辑态下该行改为保存 / 取消。

## Acceptance Criteria

- [ ] 点用户消息编辑后，气泡内可改文本；取消则原文与后续消息都不变。
- [ ] 保存非空文本后，该条及之后的消息从当前视图消失，新提问出现在截断点并开始生成。
- [ ] 编辑非最后一条用户消息时，其后的用户/助手消息同样从当前视图消失。
- [ ] 流式生成中编辑按钮不可用。
- [ ] 有正文的助手消息可复制纯文本；编辑和复制都不覆盖正文。
- [ ] 普通发送、中止恢复输入、会话切换、选段引用提问仍可用。
- [ ] `npm test` 与 sidecar 协议测试通过；`npm run build` 通过。

## Out of Scope

- 旧分支左右箭头 / 树浏览。
- `fork` 成新会话文件。
- 编辑助手消息、一键重新生成（不改提问）。
- 把选段引用持久化进 `serializeMessages`。
- 改底部输入框的 Enter 发送行为。

## Decisions

- D1: 保存 = 从该条截断当前可见历史并重发。
- D2: 本轮改 sidecar / Rust / 前端协议。
- D3: 不做分支切换器。
- D4: 按钮在气泡/正文下方固定行里，不叠字。
- D5: 任意可见用户消息都可编辑。
- D6: 前端消息对象上还在的选段，重发时原样带上。
